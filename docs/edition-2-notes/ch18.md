Coordinator opened current primary documentation while original17 was underway:

- [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)
  documents explicit breakpoints for GPT-5.6 onward, a 1,024-token eligible-prefix
  minimum, up to four writes, and no caching when explicit-only mode has no
  breakpoints. Earlier models support implicit caching only. Cache writes use
  their own rate rather than adding a surcharge to full input pricing. Its
  current examples use Responses API; verify the actual Chat Completions field
  contract and chosen model before coding or claiming that route’s support.
- [Haiku 5.5 model specifications](https://platform.claude.com/docs/en/models/haiku-5-5/overview)
  specify a 512-token caching minimum. USD per million for prompts at most
  100,000 tokens: input0.10, output0.50, five-minute write0.125, read0.01;
  above100,000: input0.50, output2.50, write0.625, read0.05. A single constant
  low-price row would misprice large requests. Preserve the prompt-length tier
  when selecting prices; do not generalize the bounded live prompt’s cheap rate.
- [Gemini caching](https://ai.google.dev/gemini-api/docs/caching) lists
  Gemini3.8Flash’s 4,096-token minimum and recommends stable early content and

  use GenerateContent’s own usage contract for the existing renderer.
