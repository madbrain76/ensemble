## Verified findings

### 1. Native semantic boundaries and final-ID associations are not preserved

**Gemini:** `main/internal/engine/sse.go:301–338` merges every contiguous text/thinking entry of the same kind, including separate entries within one frame. It neither restricts continuation to a later frame's first entry nor checks whether an existing signature has closed that part. Its signature-only branch unconditionally attaches to the previous part, potentially replacing a previous signature. Consequently two explicit text entries collapse; signed text followed by unsigned/signed text can alter the signed bytes or overwrite the signature. This contradicts Chapter 6:438–453 (explicit array boundaries, compatible unsigned continuation, trailing signatures closing exact bindings).

`main/internal/engine/parse.go:285–301` also checks `functionCall` before `thought`, and rejects a standalone first signature-only part as unknown. A thought-marked call-shaped payload therefore becomes an executable call rather than opaque replay material; a standalone signature-only payload cannot survive shared final decoding. Chapter 6:279–280 and 320–328 require opaque-first classification; 451–453 explicitly require standalone signature-only retention. This plain-decoder limitation is inherited, but is a current Chapter 6 requirement, not excused by predecessor acceptance.

**OpenAI final IDs:** `main/internal/engine/sse.go:456–490` remaps canonical parts to accumulator IDs by type (or call ID), matching all opaque parts without their native identity. `parse.go:238–247` finalizes `reasoning_content` before `reasoning`, irrespective of arrival. If `reasoning` arrives first and `reasoning_content` later, their final IDs are exchanged. That breaks per-part thinking reconstruction even though concatenated response text can look plausible. Chapter 6:371–389, 397–415 requires stable response-local delta/final identity, with zero valid.

**Recommendation:** keep native semantic identity through final decoding instead of recovering it by kind; make Gemini continuation/binding rules explicit locally and preserve opaque-first native payloads. Do not add actor/vendor coupling. These are source-derived trigger cases, not executed fixture results.

### 2. OpenAI streamed refusal is displayed but dropped from final history

`main/internal/engine/sse.go:220–237` accepts `delta.refusal`, accumulates it as text, and emits deltas. `finish` at 369–389 deliberately excludes key `"refusal"` from content but never writes `message.refusal`. In contrast, plain `parseOpenAI` at `parse.go:231–236` preserves refusal as text. A refusal-only stream therefore reaches the common decoder without usable text; mixed content/refusal silently loses the refusal. Chapter 6:274–280 and 339–343 require final semantic parity, not merely early output. Preserve the native refusal field through the existing common finalizer.

### 3. Tool handlers can start before their call is recorded and saved (inherited)

`main/internal/tool/dispatch.go:167` calls `Jobs.Start` while preparing a ticket. `main/internal/jobs/jobs.go:45–85` publishes the job and starts its handler goroutine immediately. Only after preparation does `main/internal/agent/actor.go:520–530` emit `ToolCalled`/`JobStarted` and save; direct invocation at `actor.go:267–280` has the same ordering. A fast write or registered handler may therefore have effects before the durable call exists. A later save failure cannot undo already released work.

Current Chapter 4:219–226 explicitly requires **reserve handle → record/save call → release handler**, including direct/registered tools, without demanding a crash-atomic transaction. This is one of the newly committed short teaching clarifications, not a claim that all previous prose spelled out that protocol. Recommend a local reservation/release seam covering every dispatch path; keep Jobs as execution owner and Agent as durable fact owner.

### 4. System-message reduction appends instead of replacing/clearing (inherited)

`main/internal/history/history.go:259–264` appends System parts to `Ephemera`. Two updates remain simultaneously active; a System event with empty parts cannot clear the slot. Current Chapter 2:1165–1170 explicitly defines a replaceable current prompt slot and empty-clear while retaining append-only durable events. That replacement rule is a **new clarification of an old omission**, not something this review attributes to the previously explicit prose. Replace the reduced slot locally; do not rewrite durable history.

### 5. Gemini object-valued tool results lose failure truth (inherited)

`main/internal/engine/render.go:422–429` passes JSON-object text directly as `functionResponse.response`. Only the non-object wrapper contains `is_error`, so a failed object-valued result loses `Part.IsError` (and a payload's conflicting field can supply its own false value). Current Chapter 2:842–846, another short clarification, requires preserving both object payload and failure truth. Use a deterministic provider-local envelope/merge rule that cannot let payload contents erase the actual error bit.
