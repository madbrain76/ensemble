# Chapter 11 restart — independent source review

## Verdict: HOLD — scoped corrections required

Reviewed the initial compiling candidate in `solutions/edition-3/main`, against the current Chapter 11 contract and inherited Chapter 9/10 ownership. Retain the architecture: the Agent-owned manager, shared peer/transport implementation, real job admission, separate GUI adapter and asynchronous automatic-context collection are appropriate. No wholesale rewrite or additional framework is justified. The following are blocking public-contract/correctness findings, not optional feature requests.

Paths below are relative to `solutions/edition-3/main`.

1. **The promised public embedding and tunnel seams are missing.** Chapter 11 explicitly exposes `Agent.MCP().Connect(ctx, name, transport)`, `ensemble.NewMCPTransport(reader, writer, closer)` and `ensemble.MCPPipe()`. `internal/common/mcp.go:MCPManager` instead exposes `Attach`; root `mcp.go` exports `NewMCPStream` but neither promised constructor. Its transport methods also differ from the chapter's public `Send(msg)` / `Recv()` shape. An external consumer following the published embedding contract cannot compile, independently of whether the candidate itself compiles. `internal/mcp/peer.go:call` also emits string IDs (`"ensemble-N"`), whereas the Codec contract specifies incrementing integer request IDs. Likewise, `gui/mcp.go:browserTransport.Send` and `gui/web/gui/app.js:handleMCP` use private `mcp` frames (`data` outbound, `mcp` inbound), not the documented `{"type":"jsonrpc","payload":{...}}` envelope on `/ws`; a documented client cannot exchange protocol messages. Preserve these public seams and actual declaration/initialization/discovery ownership rather than substituting private names/formats.

2. **A peer can cause ungranted automatic tools to execute.** The current chapter explicitly requires the owning skill's `tools` grant to include automatic tools. In `internal/mcp/manager.go:Discover` (lines 248–253), an unlisted tool is filtered only when its `Ephemeral` field is empty. The registry's external reconciliation likewise treats a flagged automatic tool as enabled for the owning active server; `manager.Gather` then collects enabled flagged tools. Sequence: a skill grants only an ordinary tool; its declared peer also advertises an unlisted `ephemeral: round` tool; the next request automatically executes that ungranted capability. Apply the same per-server/owning-skill grant before admitting either kind. Keep admitted automatic tools hidden from model declarations and guessed ordinary dispatch.

3. **Browser unload/reload cannot reopen the existing page's tunnel.** `internal/skills/skills.go:UnloadSkill` removes the active external capability and calls reconciliation; `internal/mcp/manager.go:Reconcile` closes/removes its client. `gui/mcp.go:browserTransport.Close` closes only the tunnel's `done` channel; it does not notify the browser. In `gui/web/gui/app.js:skillView`, the declared WebSocket server remains in `ListSkills` after unload, so `mcpAgents` remains set and suppresses another `mcp_open`. Reload then reaches manager discovery with no connection, and the generic dialer cannot dial `websocket`. Sequence: connect browser → load GUI skill → unload → reload on the same open page. A page replay/reconnect should not be required to make that later load work. Preserve pending compiled instructions while restoring external reconnect ownership.

4. **The browser snapshot does not meet its actionable, bounded public contract.** `gui/web/gui/app.js:guiSnapshot` returns actual IDs for some controls, but generates `dom-N` identities in a `WeakMap` for anonymous controls without putting those identities into the DOM or supplying a usable CSS selector. Dynamic Speak/disclosure controls therefore lack the selectors required by `gui_click` / `gui_input`. Separately, the chapter explicitly requires a Markdown snapshot capped at **4096 UTF-8 bytes** with character/artifact elision disclosure. The candidate serializes up to 160 records with up to 1200 characters of text/value each; `handleMCP` returns the entire `JSON.stringify(guiSnapshot())` with no total-byte cap. Just several full previews exceed the contract. Existing node/text clipping metadata and the live speech queue probe are useful; retain them, but provide real selectors and the required bounded, honest snapshot. This is not a request for more browser features.

5. **Reverse aliases bypass the incoming service handshake.** `internal/mcp/manager.go:localHandler` unconditionally treats `tools/builtin/list` and `tools/builtin/call` as initialized. `Serve` uses that same handler with initialization initially false. An incoming dedicated service client can therefore list or execute an enabled tool through the alias before sending `initialize`, although ordinary `tools/list` / `tools/call` are refused. Preserve reverse-call support on an already-established outbound connection; do not let that exception bypass the incoming service's initialization boundary.

6. **Cancellation cannot wake a sender queued behind another writer.** `internal/mcp/transport.go:stream.Send` checks `ctx.Err()` before `write.Lock`, but registers its cancellation close hook only after acquiring that mutex. `internal/mcp/peer.go:request` writes its reply using the peer's still-live context. With a backpressured peer, that response can hold the writer lock while a later outbound `peer.call` waits in `Send`; canceling the later call's context does not wake the mutex wait or run its close hook. Its pending request remains stuck until the first writer independently unblocks or the entire peer closes. This violates context cancellation on an actual shared request/reverse-response path. Make queued sends cancellable while preserving whole-message serialization; no arbitrary total timeout is required.
