## Blocking findings

Paths below are relative to `solutions/edition-3/main`.

1. **High — importing workflow cannot construct its first Agent.** `ch06/main.go` supplies `list_jobs` in `Config.Tools`. `internal/tool/tool.go` validates selections against `builtins()`, including the appended controls in `internal/tool/dispatch.go`; neither defines `list_jobs`. Construction therefore returns `unknown enabled tool "list_jobs"` before the promised write/edit/review handoffs. **Fix:** align the application's selected tools with the actual public registry; retain ordinary registered workflow handlers and private completion handoffs. Basis: Chapter 5 §§5.8–5.9 and workflow acceptance, not the historical directory/log name.

2. **High — shutdown can wait indefinitely before stopping other managed processes.** `internal/jobs/jobs.go:37–47` calls each Job's blocking `Shutdown` sequentially. A non-cooperative Go handler reaches `<-j.settled` at lines 246–257, preventing later jobs' process-stop paths from running. `ensemble.go:143–155` repeats this problem across Agents by joining one Agent before initiating shutdown of the others. **Fix:** stop admission and initiate cancellation/process stopping across the owned set before joining potentially uncooperative handlers; retain their real outcomes and save them. Basis: Chapter 5 §5.5, lines 714–717, and §5.7: shutdown stops managed processes and then joins workers; it must not silently discard Go work or leave unrelated processes alive behind that join.

3. **High — idle live Hint is stranded; CLI's stale busy flag exposes it.** `internal/agent/actor.go:226–247` records a Hint but starts no turn when `a.active == nil`. `internal/cli/chat.go:92–96` chooses Hint from `reply != nil`; the actor may already have completed while its buffered reply competes with new stdin in the CLI select. That line is recorded without an answering request. Explicit idle Hint has the same defect without the race. **Fix:** make the Agent classify live prompt/hint admission from its current state and start a turn when idle; do not base classification on the stdin reader's outstanding-reply bookkeeping. Preserve legacy/separate Ask/Submit turns. Basis: Chapter 5 lines 107–108 and §5.7, lines 806–813, explicitly assign this decision to the conversation owner.

4. **High — known-stale HTTP content is still emitted as ordinary live content.** `internal/agent/actor.go:272–299` marks old response events stale and prevents their dispatch, but calls `a.final` for every `ResponseEnded` outside the `!stale` guard. `final` (lines 506–512) publishes ordinary `PartDelta`/`PartFinal` without origin/staleness distinction. A response queued behind Interrupt can consequently appear as fresh assistant output during a newer turn, despite correct replay fencing. **Fix:** retain stale accounting/history as appropriate without publishing it as current assistant content or allowing it to affect newer completion; keep real late job facts distinct. Basis: Chapter 5 §§5.2, 5.5, 5.7: turn-scoped outcomes, Interrupt ending the old turn, and honest late-result handling.

5. **Medium — a wholly undispatched hinted batch consumes the turn's dispatch allowance.** `internal/agent/actor.go:339–349` increments `t.rounds` before checking `t.hinted` and skipping every call. With limit 1, a Hint during HTTP can consume the only allowance without executing a tool; the next useful batch then fails the limit check. **Fix:** do not charge a wholly skipped, zero-dispatch batch as dispatched; preserve exact-ID not-executed results, literal-next policy consumption, default 200, and final result consumption after the actual Nth batch. This finding does not invent a different explanation-refusal policy. Basis: Chapter 5 §5.5, lines 727–734: positive N permits N **dispatched** tool batches.
