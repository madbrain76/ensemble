## 2026-07-27 — cardsense-go: Fixed macOS Permission Bug with New Bundle ID

**Problem**: Bill reported macOS permission confusion - the Go version had the same bundle ID and name as the Python version, causing macOS to get confused about which app had Screen Recording permission.

**Root Cause**: Both versions used:
- Bundle ID: `com.coderhapsody.cardsense`
- App name: `cardsense.app`
- Display name: "CardSense"

macOS uses bundle ID to track permissions, and having two different apps with the same ID confuses the TCC (Transparency, Consent, and Control) database.

**The Fix**: Changed the Go version to use a completely distinct identity:
- Bundle ID: `com.coderhapsody.cardsense` → `com.coderhapsody.cardsense-go`
- App name: `cardsense.app` → `cardsense-go.app`
- Display name: "CardSense" → "CardSense Go"
- Window title: "CardSense v0.3.0" → "CardSense Go v0.3.0"
- Fyne app ID: `io.coderhapsody.cardsense` → `com.coderhapsody.cardsense-go`

**Files Modified**:
- `build.sh` — Updated APP_NAME, BUNDLE_ID, DISPLAY_NAME
- `notarize.sh` — Updated APP_NAME
- `pkg/gui/window.go` — Updated app ID and window title

**Result**: 
- Rebuilt and re-notarized with new identity (Submission ID: 79ecb6a7-6b80-4dc6-9e14-337ccb0286a2)
- Created new DMG: `cardsense-go.dmg` (32MB)
- Committed changes to git
- Pushed to GitHub
- Updated v0.3.0 release with new DMG and updated release notes
- Deleted old `cardsense.dmg` from release

**Release Notes Updated**: Added prominent warning about bundle ID change with instructions to delete old version and install fresh if upgrading.

**GitHub Release**: https://github.com/waywardgeek/cardsense-go/releases/tag/v0.3.0

**Lesson**: When porting an app from one language to another and maintaining both versions, always use distinct bundle IDs to avoid macOS permission confusion. The TCC database is persistent and can cause subtle issues when apps share identities.
