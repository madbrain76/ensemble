### fix-run-command-truncation (messages 1-41)

Investigated and fixed an issue where `run_command` output files in `cr/io/N` were being truncated to 16KB. 

Key changes:
1.  Modified `RunningCommand` struct in `pkg/tools/types.go` to include `MaxOutputSize` and `MaxLineLen`.
2.  Updated `monitorBackgroundProcess` in `pkg/tools/command_executor.go` to append all output chunks directly to the file without truncation, while maintaining a 1MB memory buffer for pattern matching.
3.  Updated `generateBackgroundCallback` in `pkg/tools/command_executor.go` to apply truncation (both total size and line length) ONLY when generating the tool result for the LLM.
4.  Added `max_line_len` parameter to the `run_command` tool definition in `pkg/ai/systemprompt.go` for consistency with `read_file`.
5.  Verified that other tools like `read_file`, `search_files`, and `crawl_web` already follow the pattern of preserving full content while truncating only the tool result.

The fix was verified with a test script generating 3000-character lines and >16KB total output, confirming the file remains intact while the LLM receives a truncated view.

## Session 10:30 — Enhanced Memory System

Enhanced the CodeRhapsody memory system to automate context loading and prevent overwriting of daily logs.

### What We Built
- **Automated Memory Loading**: The server now automatically injects `cr/MEMORY.md` and the latest daily log from `cr/memory/` into the system prompt at the start of every session. This ensures I always have the most critical context without manual effort.
- **`write_file` Append Support**: Added an `append` parameter to the `write_file` tool. This allows me to easily add session highlights to the daily log without overwriting existing content.

### Decisions Made
- **Concatenation over Session Files**: Decided to concatenate session highlights to a single daily log (`cr/memory/YYYY-MM-DD.md`) for better searchability and to keep the daily story in one place.
- **Injection Priority**: Placed memory injection at Priority 4 in `GetSystemPrompt`, ensuring it appears after user instructions but before model-specific addendums.

### Technical Notes
- Fixed a syntax error in `pkg/ai/systemprompt.go` where backticks inside a backticked string were breaking the Go compilation. Switched to single quotes for internal paths.
- Fixed a variable redeclaration error in `pkg/tools/file_ops.go` in the `executeWriteFile` function.
- Updated `GenericToolGuidancePrompt` and `compress_context` tool descriptions to reflect the new memory behavior and the requirement to append to logs.

## Session 11:15 — Markdown History Logging

Implemented centralized Markdown history logging to provide a human-readable transcript of LLM interactions.

### What We Built
- **`Message.ToMarkdown()`**: Added a method to the `Message` struct in `pkg/database/ai.go` that converts multi-modal messages (text, images, tool calls, tool results) into a clean Markdown format.
- **Automated History Appending**: Updated `Project.AddMessageToHistory` in `pkg/database/project.go` to automatically append the Markdown version of every message to `<data directory>/history.md`.
- **Startup Truncation**: Modified `newLogger` in `pkg/database/logger.go` to truncate `history.md` on startup, ensuring it stays in sync with other log files.

### Decisions Made
- **Centralized Implementation**: Placed the logic in `pkg/database` to ensure all LLM clients (Claude, Gemini, OpenAI) benefit from this feature without individual modifications.
- **Formatting Choice**: Used a clear visual style for tool calls (JSON blocks) and tool results (code blocks) to make the history easy to scan.
- **Persistence Safety**: The history appending logic respects the `ShouldPersist` check to avoid polluting the filesystem during tests.

### Technical Notes
- Added `strings` import to `pkg/database/ai.go` for `strings.Builder` and `strings.ToUpper`.
- Verified the implementation with `go test ./pkg/database/...`.
