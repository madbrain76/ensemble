## 2026-07-27 — cardsense Go Port: Fixed Bundle Data Directory Bug

**Problem**: Bill reported the .app was taking a very long time to start. He suspected it couldn't find the bundled hash files and was downloading from Scryfall.

**Root Cause**: In `cmd/gui/main.go`, the dataDir was **hardcoded** to the Python version's path:
```go
homeDir, _ := os.UserHomeDir()
dataDir := filepath.Join(homeDir, "projects", "cardsense", "hashindex", "data")
```

This meant the app NEVER used the bundled hash files, even though they were correctly included in the .app bundle at `Contents/Resources/data/`.

**The Fix**: Changed `cmd/gui/main.go` to use empty string for dataDir, allowing the bundle-aware `hash.DataDir()` function to auto-detect the correct location:
```go
// DataDir will be auto-detected:
// - Bundle mode: .app/Contents/Resources/data/
// - Dev mode: ~/projects/cardsense/hashindex/data/
dataDir := ""
```

**Verification**: Created test that confirmed:
- ✅ Bundle mode detected correctly when running from .app/Contents/MacOS/
- ✅ Found both hash files (phash_index.npz, phash_meta.json)
- ✅ Successfully loaded 53,770 cards instantly

**Added Debug Logging**: Enhanced `pkg/hash/index.go::DataDir()` with fmt.Printf statements to show which path is being used (bundle vs dev mode).

**Result**: App now starts instantly from Finder, using bundled hash files. No download needed.

**Files Modified**:
- `cmd/gui/main.go` — removed hardcoded dataDir, use auto-detection
- `pkg/hash/index.go` — added debug logging to show detected path

**Rebuilt**: `dist/cardsense.app` with the fix (59MB, ready for testing)

**Lesson**: When porting from Python, don't assume paths. The Python version was always running from the project directory during development, but the .app bundle runs from a completely different location. The bundle-aware detection logic was there but wasn't being used because the path was overridden at the entry point.
