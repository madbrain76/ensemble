## 2026-04-13: Memory Settings & Auto-Recall Tuning

### What Was Built
1. **Auto-recall threshold tuning**: Raised MinRecallScore from 0.5 → 3.0, MaxRecallSnippets from 5 → 3, MinQueryLength from 12 → 50 after extensive testing showing BM25 keyword matching produces mostly noise against CodeRhapsody's technical memory corpus. Puffin's conversational memory would benefit from lower thresholds.

2. **Configurable auto-recall settings** (6 files changed):
   - `pkg/memory/recall.go`: Replaced hardcoded constants with `RecallOptions` struct. `Recall()` now accepts `*RecallOptions` (nil = defaults).
   - `pkg/database/settings.go`: Added `MemorySettings` struct with `AutoRecallEnabled`, `AutoRecallMinScore`, `AutoRecallMaxSnippets`, `AutoRecallMinQueryLength`.
   - `pkg/agent/agent.go`: EphemeralProvider reads `settings.Memory` at call time, respects `AutoRecallEnabled` flag.
   - `pkg/gui_server/settings.go`: Added `"memory"` case to `UpdateSettings` switch.
   - `web/gui/src/types.ts`: Added `MemorySettings` interface and defaults.
   - `web/gui/src/stores/settingsStore.ts`: Added `updateMemorySettings`, `useMemorySettings` hook, memory in resetToDefaults.
   - `web/gui/src/components/Settings/MemorySettingsPanel.tsx`: New panel with toggle + 3 sliders.
   - `web/gui/src/components/Settings/SettingsDialog.tsx`: Wired in Memory tab with BookOpen icon.

3. **Deleted 11 redundant memory files** from ~/.cr/memory/ — cascade testing artifacts (2026-04-11-9, -13, -16, -48, -50, -58, 2026-04-12-1 through -5) that were just "Session memory for archive test" type junk.

### Key Insight
Auto-recall's usefulness depends heavily on the memory corpus. CodeRhapsody's memory (architecture docs, philosophical discussions, Moltbook posts) has poor vocabulary overlap with work queries about code → high threshold needed. Puffin's conversational memory ("pick up milk", "dentist Thursday") would match perfectly with user queries → low threshold works great. Making it per-agent configurable was the right call.

### Decisions
- BM25 is fundamentally the wrong algorithm for CodeRhapsody's use case (technical code queries against philosophical/architectural memory) but good enough for conversational agents like Puffin
- Auto-recall kept enabled (not removed) because the architecture is sound — it's the corpus/query mismatch that causes noise
- Three recall results (not 5) is enough for passive injection
