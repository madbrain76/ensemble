## 2026-07-27 — cardsense: Fixed Segfault Crash in Detector Loop

**Problem**: App crashed with segmentation fault when clicking Start:
```
SIGSEGV: segmentation violation
gocv.io/x/gocv.(*Mat).Empty(0x14000f559a0?)
```

**Root Cause**: In `pkg/detector/detector.go` line 323, the code tried to check `debugCrop.Empty()` without verifying debug mode was enabled:

```go
// WRONG - crashes when debug mode is OFF
if !debugCrop.Empty() {
    debugCrop.Close()
}
```

The `debugCrop` variable is declared at line 198 but only initialized if `d.debug` is true:
```go
var debugCrop gocv.Mat
if d.debug {
    debugCrop = cropGray.Clone()  // Only set in debug mode
}
```

When debug mode is OFF (the default), `debugCrop` remains a zero-value Mat with a null internal pointer. Calling `.Empty()` on it triggers a segfault in the CGO call to OpenCV.

**The Fix**: Added debug mode check before accessing debugCrop:
```go
// CORRECT - only check if debug mode is enabled
if d.debug && !debugCrop.Empty() {
    debugCrop.Close()
}
```

**Why Other Uses Were Safe**: Two other places checked debugCrop (lines 284 and 309), but they already had `d.debug &&` guards, so they were safe. Line 323 was missing this guard.

**Rebuilt**: `dist/cardsense.app` with the fix (59MB)

**Lesson**: When using OpenCV/gocv Mats that are conditionally initialized, ALWAYS guard method calls with the same condition. A zero-value Mat has a null pointer and will segfault if you try to call methods on it.
