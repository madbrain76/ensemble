## Session: Tool Skills Design — Composable Agent Capabilities

### What Was Designed
A complete architecture for decomposing CodeRhapsody's monolithic tool/prompt system into composable skills. Design doc at cr/docs/tool-skills-design.md, APPROVED by Bill.

### Key Architecture Decisions
1. **Tool categories become skills**: 11 tool-* SKILL.md files in pkg/skills/builtin/, each with a `tools` frontmatter field listing the builtin tools it provides
2. **Skills control tool availability**: ToolRegistry keeps all 35 tools registered, but new `enabledTools` map controls which are available. Skills enable tools on load, disable on unload.
3. **Generic $VAR substitution**: AgentConfig.Vars = map[string]func() string. Built-in vars ($DATE, $USER_NAME, $DATA_DIR, $CWD, $PROJECT_PATH, $MODEL_GUIDANCE) auto-registered, user can override or extend. Replaces all hardcoded prompt assembly.
4. **CodeRhapsody becomes just another agent**: main.go specifies Skills list, no special code path. Same as Puffin, family-helper, any custom agent.
5. **EnableWebSearch removed**: web access = "tool-web" in Skills list
6. **Onboarding code deleted**: Bill said it's not needed — CR is becoming an accessibility tool
7. **Model addendums become $MODEL_GUIDANCE var**: function looks up model ID, returns text or empty string
8. **Safe mode stays as flag**: security floor at executor level, not configuration mechanism

### Bill's Design Contributions
- Tool categories as skills (his idea from the start)
- $VAR substitution should be fully generic with func() string map (his refinement)
- Builtins registered upfront but not enabled unless listed in a skill (his simplification)
- CodeRhapsody as just another agent client of the Agent interface (his vision)
