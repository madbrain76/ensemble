### The key intellectual moves in the design (my contributions)
- **Unit of scale is the INCIDENT, not the enterprise.** Swarm spawned per incident, dies with it. House = 1 occasionally; Amazon = 10,000 concurrent. Nothing global except control plane, schema registry, policy engine, audit spine. This is what makes one architecture span six orders of magnitude.
- **Resolving Bill's central tension** (he wants emergent sophistication; emergence is exactly what breached Hugging Face): **split emergence by axis — unbounded in HYPOTHESIS space, zero in ACTION space.** PI+SA turned inward. The swarm thinks without limit and acts only through a narrow typed gated aperture.
- **Swarm view = one state object, three projections** (visual for analyst, textual injected into primary agent's context per Ch 7, machine for Overwatch). Reuses the duet §7b vterm pattern. Prevents analyst and copilot looking at different worlds.
- **Two axes: CONCERN (findings) × CRITICALITY (proposed actions).** The payoff quadrant is low-concern/high-criticality = where an injected agent surfaces. Single-axis severity hides it.
- **Self-reported concern is a claim, not a fact** — show it alongside DERIVED concern computed from ground truth; divergence is itself the alert. Same discipline as join_agents' `submitted`.
- **Naming: Watcher (per-agent) + Overwatch (fleet).** Avoids collision with our existing "judge" (eval scorer) and "supervisor" (actor-model parent). Gartner says "guardian agent."
- **Self-healing parser is the most dangerous component** — reads 100% attacker-influenceable content and durably writes the layer every decision depends on = textbook PI+SA. Gated: deterministic mismatch detection, quarantine-never-drop, batch-not-per-message, propose-only, golden-corpus regression gate, additive auto-promotes / subtractive never does, shadow rollout, signed revertible versions, alert on heal rate.

### Research findings that corrected me
- **NIST SP 800-61r3 (Apr 2025) RETIRED the 4-phase containment/eradication/recovery model** — now a CSF 2.0 Community Profile (Respond/Recover). r3 endorses automated containment (RS.MI-01 C1) AND requires a manual path (R1) — so our autonomy ladder is standards-aligned. NIST expects containment to carry a TTL. Two verification gates AFTER action (RC.RP-03/-05).
- **CrowdStrike 19 Jul 2024**: it was a CONTENT/channel-file update, not code — **it bypassed code-release governance because it was "just content."** 8.5M hosts; recovery couldn't be automated. → **For us, prompts/policies/playbooks/templates ARE content. Govern like code.**
- **McAfee DAT 5958 (2010)**: ePO "can not be used to undo this bad signature because affected system will lose network connectivity." → **The remediation channel must not depend on the thing it breaks.** (Meta Oct 2021 corroborates.) Strongest independent argument for the OOB control plane.
- **Microsoft ships the automation line as product behavior**: ≥99% confidence, auto-isolation "works only on end-user workstations" (refuses servers), critical-asset exclusions, email purge approval-gated. Adopt as our default config.
- **False-success traps** (the best material): EC2 SG change does NOT kill established connections — attacker C2 survives while console says isolated; refresh-token revocation leaves access tokens alive ~1h (CAE→15min but raises lifetime to 28h); MDE `machine` has NO isolationStatus field and auto-lifts at 7 days; Linux iptables change silently un-contains; CrowdStrike `hide_host` sits next to `contain` and silences reporting while host stays networked; Okta param is `oauthTokens` (not oauth2Tokens) defaulting FALSE; Kerberos TGT survives disable ~10h; email purge 10-item/mailbox cap; Vault /sys/rotate rotates the barrier key not your secret. → 4-value enum VERIFIED_EFFECTIVE/ACCEPTED_UNVERIFIED/INCONCLUSIVE/FALSIFIED, never a boolean.
- **Meta-trap: "the alert stopped firing" is not proof of remediation.** Gate absence-based conclusions on proven detector liveness.
- **ITIL: automated remediation = a PRE-AUTHORIZED STANDARD CHANGE**, not "skipping approval." Approval happened at design time on the policy. This independently justifies the pre-authorized-playbook design.
- **CrowdStrike read-only RTR tier has no `kill` in its command list** → prefer structural constraints (credentials that can't do it) over instructions telling a model not to.
- **OOB: prompt injection IS in-band signaling — the blue box reborn.** 2600Hz tone in the voice path seized a trunk; SS7 fixed it by moving signaling to a separate network. Same fix: move authority out of the data channel (CaMeL, arXiv:2503.18813). **"A log line must never be able to authorize an action."**
- **Separate IdP is the single highest-value OOB decision.** SSO-ing your OOB tool to corporate Okta "for user lifecycle management" silently destroys the property you paid for.
- **A3 attack most designs miss: WEAPONIZED remediation** — attacker induces a *legitimate* approval for a damaging action. Remediation authority is an attack surface proportional to its power.
- **NIST 800-61r3 contains "out-of-band" ZERO times** — cite CISA's IR/Vulnerability Response Playbooks instead. Scattered Spider (CISA AA23-320A) "frequently join incident remediation and response calls"; LAPSUS$ same.
- **Arup deepfake (~$25M)**: the employee was ALREADY suspicious and "put aside his doubts after the video call." The call converted a correctly-suspicious human into a compliant one. Voice/face recognition is dead as authentication.
- **BMC = ring −3**, survives OS reinstall, no EDR. CVE-2024-54085 (AMI MegaRAC, CVSS 9.8, in CISA KEV). CVE-2013-4786 is a SPEC flaw, unfixable, tens of thousands still exposed as of Aug 2026. PLATINUM used Intel AMT SOL as covert C2 invisible to the host network stack. → "Don't build OOB remediation you can't secure better than the thing it remediates."
- **Commercial constraints found in passing:** JA4+ — only JA4 is BSD-3; JA4S/H/X/L/SSH/T are FoxIO License 1.1, NOT permissive for monetization, patent pending. Trillian is in maintenance mode → use Tessera.
