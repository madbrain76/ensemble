## 2026-07-27 — cardsense: Fixed OCR False Positives

**Problem**: OCR was creating false positives by matching game board views (not single cards) to random card names.

**Example False Positive**:
- Image: Game board with multiple cards visible (457×708)
- OCR read: "BERNA" (from card name fragment)
- pHash: Best match "Nahiri, the Unforgiving" dist=200, margin=2
- Scryfall: HTTP 404 (no match for "BERNA")
- Result: Go code incorrectly returned "Embereth Shieldbreaker // Battle Display" as match

**Root Causes Found**:

1. **Empty name bug (Go only)**: `queryScryfall` returned a CardMeta even when Scryfall returned 404
   - When Scryfall returns error JSON, we parsed it successfully but got empty fields
   - Returned CardMeta with empty Name anyway → treated as valid match

2. **Low margin not checked**: When pHash margin is very low (e.g., 2), it means pHash can't distinguish between multiple cards
   - This happens with board views or overlapping cards
   - OCR is likely reading random text, not a single card name

**The Fixes**:

✅ **Fix 1**: Check for empty name in queryScryfall (Python + Go)
- Python: `/Users/bill/projects/cardsense/hashindex/phash.py` lines 288-290
- Go: `/Users/bill/projects/cardsense-go/pkg/hash/ocr.go` lines 159-162
- Now returns `None`/`nil` if name field is empty

✅ **Fix 2**: Added Guard 1b - minimum margin threshold (Python + Go)
- Python: `/Users/bill/projects/cardsense/hashindex/phash.py` lines 183-187
- Go: `/Users/bill/projects/cardsense-go/pkg/hash/index.go` lines 305-310
- Rejects OCR if pHash margin < 10 (prevents multi-card/board state captures)

**Verification**:
- Python: ✅ Now correctly rejects the false positive (returns None)
- Go: ✅ Now correctly rejects the false positive (returns nil)

**The Guard System (now 4 guards)**:
1. Guard 1: pHash distance ≤ 200 (not random noise)
2. **Guard 1b: pHash margin ≥ 10 (single card, not board state)** ← NEW
3. Guard 2: Aspect ratio 0.60-0.85 (card-like shape)
4. Guard 3: OCR text validation (5+ chars, 4+ letters, no double spaces)
5. Guard 4: Scryfall must return valid card with non-empty name

**Lesson**: When OCR creates false positives, check:
1. Is the image a single card or a board view? (margin check catches this)
2. Does the API actually return a valid result? (empty name check catches this)
3. Are all guards being enforced consistently? (Python and Go must match)
