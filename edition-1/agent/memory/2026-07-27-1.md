## 2026-07-27 — cardsense Go Port: Phase 2 Complete - Fixed pHash Bug

**Issue**: Go detector compiled and ran but failed to match any cards. Python version matched the same image successfully.

**Root Cause**: Bit packing order in `phash256()` function. I was packing bits LSB-first:
```go
bitIdx := uint(i % 8)  // WRONG - LSB first
```

But NumPy's `packbits` uses MSB-first packing:
```python
np.packbits((d > np.median(d)).flatten())  # MSB first
```

**The Fix** (one line):
```go
bitIdx := uint(7 - (i % 8)) // MSB first (bit 0 → position 7)
```

**Secondary Bug Found & Fixed**: I was hashing the resized canonical card instead of the original:
```go
// WRONG: fullHash := phash256(canonical)
// RIGHT:
fullHash := phash256(working)  // Hash original, not resized
```

**Debugging Process**:
1. Built `read_image` tool in CodeRhapsody (pkg/tools/file_ops.go + executor.go + tool-files skill)
2. Created diagnostic program to compare Python vs Go pHash outputs
3. Python: `[133, 64, 54, 191...]` → Snakeskin Veil (dist=142)
4. Go (before fix): `[161, 2, 108, 253...]` → Gimli (dist=210) ❌
5. After fix: `[133, 64, 54, 191...]` → Snakeskin Veil (dist=142) ✅

**Key Lesson**: When porting numerical algorithms, bit-level operations (packing, endianness, etc.) must match EXACTLY. Small differences produce completely wrong results.
