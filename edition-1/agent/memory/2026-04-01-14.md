## Session: Puffin Memory System + Agent Library Enhancements

### What Was Built
1. **EnableMemory for CR agent library**: Added `EnableMemory bool` + `MemoryDir string` to GlobalAgentConfig. Parameterized loadMemoryFiles(), Recall(), Search(), handoff daily log write, and memory compaction to use agent-specific memory directories. When DataDir is set (like Puffin's "puffin"), memory goes to {ProjectPath}/{DataDir}/memory/. Otherwise defaults to ~/.cr/memory/.

2. **Safe mode memory injection bug fix**: GetSystemPrompt() safe mode path returned early before loadMemoryFiles(). Added learnings + memory injection to safe mode path. This was why Puffin's MEMORY.md wasn't showing up in the system prompt.

3. **Tool safety flags**: handoff_task → Safe: true (Puffin needs it). All 5 sub-agent tools → Safe: false (prevent arbitrary code execution via agent spawning). Internal Go calls to manager.Spawn() for memory compaction are unaffected by Safe flag.

4. **SetContextProvider on AIClientInterface**: New method for ephemeral context injection at send time. Implemented in Claude, Gemini, OpenAI clients. Puffin uses it to inject current time + schedule into every API call without storing in history. Fixed deadlock: contextProvider must be read WITHOUT locking cc.mu since sendMessage is called with mu held.

5. **Memory compaction skill**: Copied from coderhapsody/pkg/skills/builtin/memory-compaction/ to family-helper/skills/ and deployed to xyzzy.

### Key Decisions
- EnableMemory defaults false — agents opt in. Standalone CodeRhapsody (not agent mode) always gets memory.
- MemoryDir only computed from DataDir when DataDir is explicitly set. DefaultCodeRhapsodyConfig() (no DataDir) falls back to ~/.cr/memory/.
- contextProvider is set-once-at-startup, read without lock in sendMessage to avoid deadlock.
- Schedule context injection replaces the old buildPromptWithSchedule() that baked schedule into every stored message.
