## 2026-08-09 (session 2) — Lyric bootstrap first-clone failure + resume drafted

### THE IMPORTANT FINDING: `make self-test` fails on first run of a virgin clone

Verified against a fresh `git clone https://github.com/waywardgeek/lyric.git` at public HEAD
`b09b9ff` (2026-07-09):

- **Run 1 on a virgin clone: FAILS.** Run 2 and all subsequent runs: PASS.
- Root cause: **checked-in `lyric.c` is one generation stale.** Its md5 is `25bece…`, but the
  compiler built *from* it emits `5e141c…`. Same line count (123,335), differs only in
  declaration ordering of stdlib string functions (`str_has_prefix`, `str_has_suffix`,
  `str_index_of`, `str_split`, `str_trim`, `is_whitespace`) — about 15 diff lines.
- So stage1 and stage2 are subtly different compilers on first run; after one run the tree
  has converged and it passes forever after.
- **Compiler itself is fully deterministic** — 3 compiles of the same input, identical md5.
  This is NOT a nondeterminism bug. `src/` is self-consistent.
- **Fix (verified in a throwaway clone):** `git pull && make update && commit && push`.
  After `make update`, self-test prints both "✅ FIXED POINT REACHED" and
  "✅ lyric.c matches compiler output" on the FIRST try.
- Bill's reaction: "we're just in a mid-dev point writing some difficult code" — not a crisis,
  but it MUST be pushed before the resume goes out (see below).

**Why this mattered enough to chase for ~10 tool calls:** the resume's strongest claim is that
Lyric's fixed point is self-verifying and needs no one's word. A reviewer who clones and runs
`make self-test` once currently sees a FAILURE. That is worse than never making the claim.

**Gotcha that nearly fooled me:** I first reported "self-test fails" from the local repo, then
a commit-walk showed HEAD passing, which contradicted it. Resolution: local `~/projects/lyric`
was at `2211230` (Jul 5), BEHIND GitHub `b09b9ff` (Jul 9); and my walk ran after a `make update`
had already converged the tree. **Always test a virgin clone, once, for first-run claims.**
