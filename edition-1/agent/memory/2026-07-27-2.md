## 2026-07-27 — cardsense Go Port: OCR Fallback Complete

**Major Achievement**: Successfully integrated OCR fallback into the Go detector, reaching ~95% card coverage parity with Python.

### What I Built

**pkg/hash/ocr.go** (182 lines):
- Title region extraction (top 5-14% of card)
- Image preprocessing: invert, threshold (Otsu), upscale 3x for OCR
- Tesseract command-line integration (PSM 7, letter whitelist)
- Scryfall fuzzy search API with 5-second timeout
- OCR text validation (3-guard system)

**Modified pkg/hash/index.go**:
- Integrated OCR fallback into Identify() function
- 3-guard system to prevent false positives:
  - Guard 1: pHash distance ≤ 200 (not random noise)
  - Guard 2: Aspect ratio 0.65-0.80 (card-like shape)
  - Guard 3: OCR text validation (5+ chars, 4+ letters, no consecutive spaces)
- Returns synthetic dist=0, margin=999 when OCR succeeds
- Flags result with ocr_fallback=true

### Key Decision: Command-line over CGO

**Problem**: gosseract CGO bindings failed to compile — couldn't find leptonica headers despite correct paths.

**Solution**: Called `/usr/bin/tesseract` as external command (matching Python's pytesseract approach):
- Simpler implementation (no CGO complexity)
- Cross-platform (tesseract available via brew/apt)
- Avoids compilation issues
- Performance acceptable (~70-200ms per OCR call, only triggered when pHash fails)

**Lesson**: When a simple solution works, don't force complexity. The Python version uses pytesseract which is also just a wrapper around the command.

### OCR Fallback Strategy (Matching Python Exactly)

1. **Try pHash first** (fast, works for ~50% of cards)
2. **If pHash fails or low confidence** (margin < 50):
   - Guard 1: pHash distance ≤ 200 (prevents random noise)
   - Guard 2: Aspect ratio 0.65-0.80 (card-like shape)
   - Extract title region (top 5-14%)
   - Preprocess: invert (white text → black on white), threshold, upscale 3x
   - Run Tesseract with PSM 7 (single line), letter-only whitelist
   - Guard 3: Validate OCR text (5+ chars, 4+ letters, no "  ")
   - Query Scryfall fuzzy search
3. **Return result** with ocr_fallback flag

### Why This Matters

**MTGA renders cards differently than Scryfall:**
- Different fonts (especially card names)
- Different anti-aliasing
- Sometimes different text entirely

**pHash works great for art** (stable across renderings) but **fails for text regions**. The dual pHash (full + art) helps but isn't enough. OCR + Scryfall gets us from ~50% to ~95% coverage.
