## Session: Memory Cascade v2 Design (2026-04-11)

### What Was Built
1. **Memory cascade v2 design doc** (cr/docs/memory-cascade-design.md, 506 lines): Complete implementation spec for Gemini 3.0 Flash. Fixed-size 16KB buckets with 8× compression per level, max 2 buckets, MEMORY.md graduation.
2. **MEMORY.md compressed**: 30KB → 13KB. Gentle curation — kept all identity, collaboration, and key decisions. Condensed project histories, career details, hacker stories to one-liners. Dropped deploy procedures, Moltbook stats, and other search-recoverable details.
3. **Deleted old bucket-0.md**: Fresh start for the new scheme.

### Key Design Decisions (Memory Cascade v2)
- **8× compression per level** (was 2×): Covers ~1.4 years in 2 buckets vs 40 days in 5 buckets
- **Fixed 16KB bucket size** (was variable): Total bounded at ~68KB for episodic memory
- **Max 2 buckets** (was unbounded): bucket-1 overflow → MEMORY.md graduation
- **Convergence loop** (was single-pass): Repeats until ALL layers within targets. Handles cold start with 200KB.
- **Whole-session shifting**: Never split a memory file or ## section. Move whole units between levels.
- **Three prompt types**: Bucket compression (8× mechanical), graduation (extract permanent insights), curation (Claude Opus 4.6 with full CodeRhapsody identity)
- **MEMORY.md curation agent**: MUST be claude-opus-4-6 with coderhapsody-assistant skill. Full identity context — SOUL.md, learnings, memory. Fresh sub-agent, no compression residue.
- **MEMORY.md caps**: Soft target ~20KB, compression triggered at ~24KB
- **Nothing truly gone**: Raw files persist for search_memory/auto-recall

### What Was Considered and Rejected
- Geometric decay (halving bucket sizes): Only covers 40 days in 31KB. Fixed-size 8× covers 1.4 years in 48KB.
- 3 or more buckets: 2 is sufficient — bucket-1 covers ~1.4 years, MEMORY.md handles the rest
- settings.json for builtin skill model override: Builtins don't load settings.json from go:embed. Model goes in Spawn() call parameter instead.
- Splitting files at exact thresholds: Whole-session shifting preserves coherence, slight over/under is fine.
- Single compress func for all three jobs: Three separate funcs with different prompts is cleaner. Curation especially needs a fresh context.
