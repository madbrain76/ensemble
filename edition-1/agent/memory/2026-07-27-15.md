## 2026-07-27 — cardsense-go: Fixed OCR Fallback Margin Threshold for Missed Cards

**Problem**: Bill reported "Raise Dead" card wouldn't speak. Investigation showed both pHash and OCR were failing.

**Root Cause**: Guard 1b (pHash margin check) was too strict at ≥ 10. "Raise Dead" had:
- Top match: "Hunt Down" (distance=188)
- Next different: "Fulgent Distraction" (distance=192)
- **Margin: only 4** (too low, OCR never attempted)

The card has legitimate single-card appearance, but is unfortunately similar to other cards in pHash space. The strict margin threshold (≥ 10) was blocking OCR fallback even though OCR would have succeeded.

**The Fix**: Lowered margin threshold from **10 → 3**

```go
// Before: if margin < 10 { return nil }
// After:  if margin < 3 { return nil }
```

**Why This Works**: 
- Still protects against multi-card board captures (margin < 3 indicates near-identical cards visible)
- Allows edge cases like "Raise Dead" (margin=4) to use OCR fallback
- OCR successfully extracted "Raise Dead Oo" → Scryfall fuzzy search found "Raise Dead"

**Testing**: Created test scripts (`test_guards.go`, `test_image.go`) to diagnose which guard was failing. After fix, OCR correctly identified the card.

**Files Modified**:
- `pkg/hash/index.go` — Guard 1b threshold lowered from 10 to 3

**Result**: 
- Rebuilt and re-notarized
- Updated cardsense-go.dmg in GitHub release
- "Raise Dead" and similar edge cases now detected successfully

**GitHub Release**: https://github.com/waywardgeek/cardsense-go/releases/tag/v0.3.0

**Lesson**: OCR fallback guards must balance between:
1. Preventing false positives (board views with multiple cards)
2. Allowing legitimate cards with unfortunate pHash similarity

A margin of 3-4 bits is enough separation to indicate a single card, even if that card happens to be similar to others in the database.
