### Key Design Decisions
- Memory tree: daily logs in ~/.cr/memory/ (immutable, searchable), summaries in ~/.cr/memory/tree/ (not searched)
- Summary filenames: {N}x-{start}--{end}.md (leaf count in name, no date math needed)
- Validate dates during scan to catch rogue files
- Bill's preference leans toward optimal greedy K=8 (5 nodes for 365 days, full re-read summarization)
- The trade: expensive summarization once per day vs cheap context loading every turn

### Schemes Compared (365 days → nodes loaded)

- Binary tree skip-1: 6 nodes, max 4× jumps
- K=4 rolling bins: 8 nodes
- Optimal greedy K=8: 5 nodes (Bill's latest preference)

### What Was Considered and Rejected
- JSON state file for tree tracking — Bill: just parse filenames, self-healing
- K=2 binary tree without skip: 12 nodes at 365 days, too many
- Pure binary counter (merge at 2): full cascade on powers of 2 wipes out recent detail
- Merge at 3 everywhere: guarantees every level occupied but produces too many nodes
