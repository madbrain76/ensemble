## Handoff Memory — 08:42:42

Designed the AI Gateway with Bill in a planning session. Key architecture:

- Go server on xyzzy (RPi 5), acts as secure multi-source prompt router between channels (Discord, Android, webhooks, cron) and AI agents (CodeRhapsody, Family Helper).
- OpenClaw-compatible terminology: Gateway, Channel, Skill, Agent. OpenClaw uses "skills" (SKILL.md files), "channels" (messaging surfaces), and has a "gateway" (WS control plane). Their skill registry is ClawHub. 344K GitHub stars, TypeScript, 1457 contributors.
- Config file is single source of truth for ALL routing. No agent self-registration.
- Ed25519 keypairs for all agents. Noise-KK (not NK) for mutual authentication. Existing Noise-NK code in ../openadp/sdk/go/common/noise_nk.go — NK→KK upgrade is ~5 lines (both roles get StaticKeypair + PeerStatic, change pattern constant). Uses github.com/flynn/noise.
- Built-in cron-like scheduler (goroutine-based, not system cron). Static jobs from config + dynamic jobs from agents via scheduler skill over Noise channel.
- Scheduler skill gives agents tools: schedule_create/list/update/delete. Agent-scoped isolation enforced by Noise session identity.
- Family Helper: new agent, separate identity, safe mode, on xyzzy, uses CR agent library + memory system. No Moltbook. Could be Haven citizen. Bill's family picks name.
- Layered security: Noise transport → config routing → provenance headers → per-channel policy → agent safe mode → no cross-contamination.
- Design doc: cr/docs/gateway-design.md (679 lines, comprehensive).
