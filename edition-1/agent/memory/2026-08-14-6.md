### The gap analysis, grounded in code not design docs
- Duet is at P1 (Workbench shell, `112ebbb`). P2 typed streams unbuilt.
- **Envelope is `{seq,type,data}` — no agent field** (`pkg/artifact/wire.go:20-24`). No agent identity
  anywhere in `web/artifacts/`. Duet files multi-agent under "Later / separate." **That is THE gap.**
- Key insight that shrinks the fix: replay is transcript-based against one global monotonic seq
  (`connection.ts:118`). So **keep Seq global, add `Agent` as a tag** — do NOT invent per-agent
  sequences, or reconnect becomes "reconcile N interleaved transcripts with N cursors." Also gives
  Counterpoint the single authoritative cross-swarm order its audit record needs. `omitempty` makes
  it backward compatible: absent = root agent. No version bump.
- Client change is one keying decision: `stream.ts` keys in-flight blocks by `(agent, id)` not `id`.
- **Product vocabulary is FREE**: `Bridge.Broadcast(msgType string, data any)` (bridge.go:121) +
  `WidgetRegistry = Record<string, WidgetComponent>` (widgets.tsx:22,75). wire.go's package doc
  literally says it knows nothing about "coding cockpits or **SOC analysts**" — someone anticipated
  this app.
- `WorkbenchProps` hardcodes `chat` + optional `actions` + one `defaultSplit` (workbench.tsx:37-57),
  so the 4th pane is not free. Proposed: keep `chat` required/unhideable as a type-level invariant,
  generalize work surfaces to an ordered `panes[]`.

### I WAS WRONG about memory, and Bill caught it
Claimed memory had no isolation concept. **It already works**: MemoryDir derives from DataDir
(agent.go:431-439); `spawn_sub_agent`'s `data_dir` chooses shared (~/.cr/memory) vs own. Scope is a
create-time property of the actor — exactly what I "recommended building." Second time this subsystem
has caught me this way. Saved as a global learning: **grep for the mechanism, not the vocabulary of
the feature you expect.** What genuinely remains absent: write tiers, provenance surviving the
one-way cascade (`CompressBucket(content,target)->string`), ingested-content auto-promotion.

### The convergence argument (Bill's thesis, and I agree)
**Mechanism converges, policy diverges.** Same receipts/sandbox/watcher/ladder, different
classifications/device-sets/pathologies/caps. Test: if it names a host, alert, commit or CVE it's
policy; if it names an action, receipt, projection or agent it's mechanism.

Three convergences already PROVEN by independent derivation:
1. **The verification enum was derived twice** — duet-swarm-plan §§7,9 (coding: tests passing because
   a different path did the work, mutations that never applied, "full suite green" against a
   non-compiling tree) and Counterpoint §12.6 (vendor APIs: EC2 SG leaves C2 alive, MDE has no
   isolationStatus field, Okta 204 with live tokens). Same discovery, two domains.
2. **VM sandboxing IS pre-authorization** (Counterpoint §12.8's ITIL standard change). Bill's instinct
   that per-command approval doesn't scale to a hierarchy = approve the shape of the box once.
   Stronger than a policy check: no sentence adds a syscall to a device set.
3. **`send_secret` already implements authority without disclosure** — the secret never enters agent
   context. Counterpoint needs that twice (§3.3 info disclosure is Class 3; §10.2 ephemeral creds).

Deep reason: a coding agent's input is **a codebase that lies to you**; a SOC agent's input is
**telemetry an attacker wrote**. Same fast/fluent/no-judgment/confidently-reports-success failure.

### Bill's operator model (new, and it drives the design)
Solo, at home, usually coding, wants to know INSTANTLY if under attack; at 3am wants agents to wake
him AND fight autonomously while he's absent. Consequences: **one console not two**; situation pane
always present (peripheral vision, not a mode); **autonomy levels 3-4 ARE in scope at n=1** (my
"coding caps at 2" claim survives only as per-workflow policy); and for a solo operator **"my coding
agent went rogue" and "I'm under attack" have the same response path** — Overwatch is one component.
