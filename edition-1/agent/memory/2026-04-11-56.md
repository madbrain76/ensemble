## 2026-04-11: Memory Cascade Boundary Bug Fix

### What Was Built
1. **afe18c4**: Fixed lexicographic boundary comparison bug in memory cascade. Added `compareMemoryNames(a, b string) int` that parses `YYYY-MM-DD-N` format — compares date lexicographically, then N numerically. Replaced all 4 string comparison sites (`name > boundary`, `name <= boundary`) in cascade.go and LoadCascade. Added `TestCompareMemoryNames` and `TestMultiDigitSequenceNumbers` regression tests.
2. **a97b958**: Committed Gemini's v2 cascade changes — handoff.go `makeCascadeFuncs()` with three specialized sub-agents (bucket compression, graduation, curation), updated memory_test.go from rolling summaries to cascade buckets, visible-reasoning SKILL.md section name fix.

### Root Cause
Go string comparison `"2026-04-11-8" > "2026-04-11-50"` evaluates to TRUE because `'8' > '5'`. When bucket-0's CoversThru was set to a single-digit sequence number, files with multi-digit sequence numbers were incorrectly excluded from the uncompressed window. The cascade couldn't converge because files "fell through the cracks."

### Key Insight
The bug only manifests when sequence numbers exceed 9 — which happened during the cascade convergence testing because each handoff creates a new memory file (50+ handoffs in one day). Normal usage with 2-3 handoffs per day would rarely trigger it, but the cascade's own convergence testing created the conditions that broke it.
