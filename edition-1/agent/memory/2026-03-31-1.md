## Session: Memory System Evolution Analysis

### What We Did
- Read and analyzed OpenClaw's full memory architecture doc (~/openclaw-mem.md, 48KB)
- Compared against our current three-tier system (MEMORY.md + daily logs + BM25 auto-recall)
- Identified 6 gaps with OpenClaw, prioritized by impact
- Wrote comprehensive design doc: `cr/docs/memory-evolution-design.md`

### Key Findings
1. **Pre-handoff memory flush is the critical gap**: handoff_task doesn't ensure memories are saved. Solution: required `memory` parameter on handoff_task.
2. **Weekly summaries were designed (2026-03-17) but never built**: 17 daily logs, ~100KB, no condensed summary layer between MEMORY.md and raw daily logs.
3. **BM25 auto-recall IS working**: Confirmed it surfaces snippets in user messages. Saw `[Auto-recalled memories]` block with relevant context from older daily logs.
4. **No active memory search tool**: Only passive auto-recall (3 snippets, 3KB). Need `search_memory` tool for explicit retrieval.
5. **MEMORY.md is 30KB and growing**: No governance. Need size cap + archive + auto-curation.
6. **cr/current only saved on shutdown**: Crashes lose sessions. Incremental append would fix.

### Decisions
- **Required `memory` param on handoff_task**: Atomic — one tool call guarantees both handoff AND memory save. Better than two-step write_file + handoff_task.
- **Sub-agent for memory curation at handoff**: Bill's idea. Agent is losing context anyway, so spawning a compaction sub-agent costs nothing. Produces weekly summaries + archives stale MEMORY.md sections.
- **KISS on vector search**: OpenClaw uses SQLite + sqlite-vec + FTS5 hybrid. We use BM25 only. Our corpus is ~100KB. BM25 rebuilds on every call. Add persistence only if corpus exceeds ~1MB.
- **cr/current rename deferred**: It's JSON without .json extension. ~6 references to update. Not worth breaking Bill's git snapshots and muscle memory right now.

- Bill manipulates cr/current constantly (snapshots, resets, git commits). Session management in GUI is nice-to-have for him, critical for future open-source accessibility users.
- Bill asked about the missing weekly summary layer — he'd noticed it was absent but it didn't matter during the first week. Now at 2 weeks, the gap is real.
- Bill suggested auto-curation sub-agent at handoff. No reason not to.
