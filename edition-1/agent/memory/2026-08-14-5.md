### The audit (design/integration-audit.md, 293 lines) — 2 known defects + 11 new
Wrote the audit as a first-class artifact BEFORE writing a word of the doc. Highest-value step.

**D3 is the big one and it changes the threat model.** HF's initial access was a malicious dataset
abusing a remote-code loader + **Jinja2 template injection** — i.e. a data-processing pipeline that
*executed a template against untrusted input*. That is a description of our self-healing parser. The
two facts sat 350 lines apart in the first draft and never met. All the existing §4.4 gates assume
the danger is a *wrong* template; HF says the danger is an *executing* one. New rule promoted into
§2.3: **parser templates are declarative data, never executable code** — non-Turing-complete
interpreter, no eval/shell-out/code-loader/network, sandboxed. Holds when every semantic gate fails.

**D4**: CrowdStrike's RCA ("sensor expected 20 input fields, while the update provided 21") is a
*parser field-count mismatch*. The first draft used it only as a content-governance lesson in §12.
It belongs in the parser section as the motivating case — the canonical catastrophic content update
in the industry's memory WAS the exact event our healer is built to respond to and could cause.

**D1 (known)**: "This list **is** §11.2's irreversible floor" was false. Fixed by deriving the floor
once from **two independent sources — Axis A (availability, vendor-derived) ∪ Axis B (self-protection,
injection-derived)**. Neither generates it alone. The interlock: Axis B is what an attacker wants done
*quietly*; Axis A is what they want done *loudly* (= A3 weaponized remediation's target set).

**D2 (known)**: autonomy uncoupled from verification. Fixed: at level 2+ an action isn't done until
VERIFIED_EFFECTIVE, and a rising ACCEPTED_UNVERIFIED rate auto-throttles autonomy. General form
recorded: *any signal that the swarm's picture of the world has decoupled from the world reduces what
it may do without asking.*

**D5**: global components were 4, should be 5 (identity missing — the OOB research's single
highest-value decision). Worse, §9.3's covert-channel principle means all five ARE cross-incident
channels, so "ten thousand swarms that don't talk to each other" was false. Parser registry is the
dangerous one. Skill promotion writes into other agents' system prompts.

**D6**: 3 of 6 "Class 1, all reversible" house actions were misclassified (kill process is Class 3).
**D7**: §12.1 "Class 3 never automated" conflicted with §12.6's f(reversibility, tier, blast_radius).
Resolved for the function, with the floor as hard override. Consequence surfaced in §15.3 and flagged
as open Q10 — killing a process unattended at home becomes permissible.
**D8**: console layout wired approvals into the actions pane; OOB section required separate device +
IdP. Resolved: console *displays*, OOB *grants* for Class 3 / Tier 0 / autonomy elevation.
**D9**: flat two-person above level 2 rebuilt the bottleneck level 3 exists to remove; NIST AC-3(2)
says weigh dual auth against need for immediate response. Moved two-person to the elevation *grant*.
**D10**: §3 designed auto provider failover with no staged rollout — models/prompts are content.
**D11**: routing a payload to a hosted model IS a Class 3 information disclosure → receipt, not log.
**D12**: silence detection + detector liveness are ingest properties, were filed under OOB.
**D13**: derived concern ignored verification distribution, detector liveness, heal rate, quarantine
rate. Also: containment is a lease → incident map shows contained-*until*, never a checkmark.
