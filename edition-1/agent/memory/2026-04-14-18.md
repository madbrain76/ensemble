## 2026-04-14: Puffin Upgrade Design Session

### What Was Built
1. **cr/docs/puffin-upgrade-design.md** (1,324 lines) — Complete design doc for Puffin upgrade from single-conversation family bot to multi-conversation family data platform with circle-based privacy.

### Architecture Decisions
- **Two CR agents, one process**: Family agent + Mom-Care agent, each with own DataDir/memory/history, sharing one DataService. Uses `agent.NewAgent()` pattern from examples/custom-agent.
- **Circle-based ACL in Go**: Privacy enforced at DataService layer, not by LLM instruction. Bill is in both circles, has one calendar visible to both agents.
- **AllowedSkills on AgentConfig**: Filters which builtin skills agents see in list_skills. Project/global skills always visible. Auto-loaded skills (primary + deps) hidden. Solves "Puffin shouldn't see tool-commands" without annotating every builtin.
- **propose-skill builtin**: Tier 2 self-evolution — agents propose skills (SKILL.md + Python scripts) to staging dir, human reviews and copies to ./skills/.

### Data Model
- Person (with Circles, Contacts), Calendar (per person), Event (with Alerts, GuestIDs, NoteIDs, recurrence exceptions), TaskList (owner + SharedWith), Task, Note (with Category for medication graduation)
- Recurrence exceptions: cancel/reschedule/modify individual occurrences
- Staged Alerts replace flat ReminderMinutes: notification/alarm/escalation types
- Notes owned by people, flow through events and tasks to guests
- Medications start as Notes with category="medication", graduate to structured data later

### Key Rejected Approaches
- Separate Puffin processes (sync protocol too complex)
- Single instance with LLM-enforced privacy (LLM can't enforce ACL)
- Safe annotation on builtin skills (AllowedSkills is cleaner)
- Separate alarm data structure (zero-duration events with AlarmConfig instead)
