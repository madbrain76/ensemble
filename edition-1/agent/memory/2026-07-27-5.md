## 2026-07-27 — cardsense Go Port: Fixed Octoprophet OCR Fallback

**Problem**: Octoprophet card not matching in MTGA (both Python and Go versions).

**Root Cause Investigation**:
- pHash: Best match was Octoprophet with dist=172, margin=10
- pHash threshold (dist≤280, margin≥20) FAILED due to low margin
- OCR fallback should have triggered, but Guard 2 (aspect ratio) was rejecting the card

**The Bug**: Aspect ratio guard was too strict
- Octoprophet image: 457×708 pixels → aspect=0.645
- Guard 2 threshold: 0.65-0.80
- Result: 0.645 < 0.65 (failed by 0.005!) ❌

**Fix 1**: Widened aspect ratio guard from 0.65-0.80 to **0.60-0.85**
- `/Users/bill/projects/cardsense/hashindex/phash.py` (line 187)
- `/Users/bill/projects/cardsense-go/pkg/hash/index.go` (line 310)
- Rationale: Real MTGA cards have slight variations in screen capture depending on resolution and detection box calibration

**Fix 2**: Added missing Accept header for Scryfall API (Go only)
- `/Users/bill/projects/cardsense-go/pkg/hash/ocr.go` (line 115)
- Scryfall API requires BOTH User-Agent AND Accept headers
- Error was: HTTP 400 "You submitted an invalid request. HTTP requests to api.scryfall.com must contain a User-Agent and Accept header"
- Fixed by adding: `req.Header.Set("Accept", "application/json")`

**Verification**:
- Python: ✅ Now identifies Octoprophet via OCR fallback (dist=0, margin=999, OCR text="Octoprophet CVC")
- Go: ✅ Now identifies Octoprophet via OCR fallback (dist=0, margin=999)

**Lesson**: When debugging OCR fallback failures:
1. Check pHash distance and margin first
2. Verify ALL guard conditions (aspect ratio can fail by tiny margins)
3. For API calls, read error responses — Scryfall gave a clear message about missing headers
4. Test both Python and Go to ensure behavioral parity
