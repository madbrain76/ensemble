## 2026-07-27 — cardsense: Cleaned Up Verbose Terminal Logging

**Problem**: Bill reported terminal spam with logs like:
```
2026/07/27 06:27:14 [TIMING] Frame 38: capture=379.189042ms, preprocess=537.25µs, identify=43.562583ms, TOTAL=423.288875ms
```

**Root Cause**: The detector had extensive debug logging that printed on every frame and every card detection:
- `[TIMING]` logs on every frame with a card
- `[DETECT]`, `[SPEAK]`, `[TIMING]` logs on every card change
- `[STATUS]` log duplicating GUI status updates
- `[INIT]` logs showing screen dimensions and box coordinates
- `[DataDir]` logs showing path detection

**The Fix**: Removed verbose non-error logging, keeping only:
- ✅ Errors (kept)
- ✅ Calibration events (kept, rare)
- ✅ Debug mode logs (kept, only when --debug flag used)
- ❌ Frame timing (removed)
- ❌ Card detection (removed)
- ❌ Status updates (removed, redundant with GUI)
- ❌ Init details (removed, not user-facing)
- ❌ DataDir detection (removed, confirmed working)

**Files Modified**:
- `pkg/detector/detector.go` — removed [STATUS], [TIMING], [DETECT], [SPEAK], [INIT] logs
- `pkg/hash/index.go` — removed [DataDir] logs
- Also removed unused timing variables (t0, tCapture, tPreprocess, tIdentify)

**Result**: App now runs quietly with minimal terminal output. Only shows:
- Errors (if any occur)
- Calibration messages (first match only)
- Debug logs (only with --debug flag)

**Rebuilt**: `dist/cardsense.app` (59MB, ready for final testing)

**Lesson**: For GUI apps, terminal logging should be minimal by default. Users don't need to see every frame processed or every card detected - that's what the GUI status display is for. Keep logs for errors, initialization failures, and explicit debug modes only.
